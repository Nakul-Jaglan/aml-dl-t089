# **1\. Project Team Formation**

* Students must work in **teams of exactly 5 members**.  
* Students can make teams in their sections only.  
* A Google Form will be used for the project/team selection process.  
* Students may either select a **faculty-provided project idea** or propose their **own project idea**.

# **2\. Faculty-Provided Project Ideas**

A set of faculty-provided project ideas will be shared with students as a PDF. The project ideas document contains the relevant problem statements, requirements, and other information needed for project selection. The same document will also be made available through the designated course communication channel.

# **3\. Students Proposing Their Own Project**

Teams that wish to work on their own project idea should **not fill the regular project-selection Google Form initially**. Instead, one member of the team should contact the concerned faculty member and submit the proposed project details on behalf of the entire team.

* Provide a **valid and clear reason** for choosing an independent project idea.  
* Prepare the problem statement using the **same format as the problem statement template** shared with students.  
* The team must consist of **exactly 5 members**.  
* **Only one student** from the team should communicate with the faculty and provide the details of all five team members. Other members should not send separate emails regarding the same proposal.  
* Acceptance or rejection of the proposed project idea will be **entirely at the discretion of the faculty**.

# **6\. Evaluation Structure**

The project will be evaluated in **two phases**. Both Phase 1 and Phase 2 evaluations will be conducted **after the Mid-Semester examinations**. The exact evaluation dates have **not yet been finalized** and will be communicated separately.

## **Phase 1 \- Machine Learning Evaluation**

**Phase 1 will involve Machine Learning evaluation only.** The evaluation will focus on the student's ability to understand, implement, justify, and validate the ML component of the project.

* Literature Review  
* Dataset Quality & EDA  
* Feature Engineering  
* Theoretical Rigor  
* Model Application  
* GitHub Repository & Code Quality  
* Project Presentation  
* Viva Voce  
* Project Report (LaTeX/IEEE format)

## **Phase 2 \- Deep Learning Evaluation**

Phase 2 will involve Deep Learning evaluation. Students may additionally implement a Hybrid Approach combining appropriate ML and DL techniques where such an approach is technically feasible and relevant to the project problem.

**Hybrid Approach & Additional Marks:** Teams that successfully implement a meaningful and technically justified Hybrid Approach will be awarded additional marks in the Phase 2 evaluation. The additional marks will be awarded based on the quality, technical soundness, successful implementation, and demonstrated value of the hybrid approach. Simply combining ML and DL models without a valid rationale or successful implementation will not qualify for additional marks.

* Architecture Logic  
* Hybrid Innovation  
* Ablation Studies  
* Deep Learning Literature Review  
* DL Dataset & Regularization  
* Technical Validation  
* Theoretical Rigor  
* GitHub Repository & Code Quality  
* Project Presentation  
* Viva Voce  
* Project Report (LaTeX/IEEE format)

# **7\. Individual Viva Voce Assessment**

The **Viva Voce will involve individual assessment**, even though the project is completed as a team. Each student must therefore be able to explain and demonstrate their understanding of the project, including the methods, implementation, experiments, results, and relevant theoretical concepts.

The GitHub repository, project report, presentation, experiments, results, and other required project components should clearly demonstrate both the **team's overall work** and each member's **individual understanding and contribution**.

Project ideas PDF and the Google Form link will be shared through the designated communication channel.
